# 맞춤형 교내외활동 탐색 프로토타입

고정 공고 19건(실제 공고 12건 + 예시 공고 7건)으로 동작하는 클릭형 프로토타입이다. 기획은 `../docs/PROJECT_SPEC.md`를 따른다.

> 기획서는 "고정 공고 12건"이다. 학년·재학 상태·대상 학과 필터를 확인하려고 예시 공고 7건(`s01`~`s07`)을 더했다. 기획서 기준 12건으로 되돌리려면 `data.js`에서 `s01`~`s07`을 지운다(테스트는 예시 공고가 있다고 가정하므로 함께 수정해야 한다).

## 실행과 검증

- 컴퓨터에서 실행: `index.html`을 브라우저로 연다. 서버와 빌드는 필요 없다. 단, 같은 폴더의 `styles.css`, `app.js`, `images/` 등이 함께 있어야 한다.
- **휴대폰에서 실행: `standalone.html` 한 파일만 옮겨 연다.** `index.html`만 폰으로 보내 열면(`content://` 주소) 옆에 있는 CSS·JS·이미지를 찾지 못해 스타일 없이 글자만 보인다. `standalone.html`은 모두 한 파일에 합친 버전이라 이런 환경에서도 동작한다(약 2.2MB, 포스터는 폭 900px 축소본).
- `standalone.html` 만들기: `npm run build:standalone` (또는 `python tools/build_standalone.py`). Python과 Pillow가 필요하다. 데이터나 화면을 고친 뒤에는 다시 만들어야 한다.
- 테스트: `npm test` (Node 내장 테스트 러너, 외부 의존성 없음)

### 모바일 점검 (2026-11-12)

`test/mobile-audit.js`로 5가지 화면 크기에서 점검했고 모두 문제가 없었다: 320×568, 360×740, 412×915, 768×1024(태블릿도 모바일 배치), 844×390(가로 방향). 검사 항목은 가로 스크롤 없음, 터치 대상 44px 이상(칩 36px 제외), 조건 패널의 "결과 N건 보기" 버튼이 화면 안에 있음, 적용 후 목록 제목이 고정 바에 가려지지 않음, 상세 시트가 화면 아래에 붙고 닫기 버튼이 스크롤해도 보임, 포스터가 화면 안에 들어옴, 결과 없음 안내와 초기화 후 전체 복귀다. 데스크톱(1280px) 배치는 그대로다.

모바일 대응 내용: 접이식 조건 바(선택 개수·결과 건수 표시)와 "결과 N건 보기" 버튼, 하단 시트로 열리는 상세 정보, 안내 문구 접기, 입력란 16px(iOS 자동 확대 방지), `dvh` 높이(주소창 변화 대응), 안전 영역 여백, 더블탭 확대 지연 제거, 한글 단어 단위 줄바꿈.

## 남은 제약

- **탐색 시간 20% 단축**은 이 프로토타입에서 측정한 값이 아니다. 학생 5명이 기존 방식과 프로토타입으로 비슷한 과업을 수행하는 **실제 사용자 평가에서 검증할 목표**다. 5분 이내·80% 목표도 같다.
- **학년·대상 학과 필터는 실제 공고 12건만으로는 결과를 바꾸지 못한다.** 실제 공고는 학년 제한이 없거나(1~4학년) 불명확(`null`)하고, 학과를 제한한 공고가 하나도 없다(파두단은 "전체학과"). 두 필터가 동작하는 것은 가상 예시 공고(`s01`~`s07`)를 포함했을 때만 확인된다. 실제 공고만 쓰는 최종 평가에서는 이 두 필터가 쓸모없다는 점을 감안해야 한다.
- 예시 공고 7건은 필터 확인용이라 학년·학과 한정이 실제 목포대 공고와 다를 수 있다. 기획서의 "고정 공고 12건"과 달리 총 19건이다.
- **학과 목록은 웹 검색 결과를 바탕으로 한 것이라 실제와 다를 수 있다.** 자연과학대학은 학과를 확인하지 못해 단과대학 단위로만 두었다. 학과 목록은 `data.js`의 `DEPARTMENTS`에서 고친다.
- **재학 상태의 `false`(제외)에는 추론이 포함된다.** 원문이 명시한 제외(국민대 "휴학생·대학원생 제외")와, 모집 대상이 재학생·대학생으로 한정되어 일반인이 해당하지 않는 경우(r03, r04, r05, e03, e05, e07)를 같은 `false`로 처리했다. 원문이 모호한 항목은 `null`(확인 필요)로 두었다.
- 신청 마감일이 기준일(2026-11-12) 이전인 공고가 12건 중 8건이라 "마감"으로 표시된다. 지난 공고를 제외하는 기능은 범위 밖이다.
- 공고 정보는 사용자가 제공한 정리표를 바탕으로 했다. 원문 페이지 접속과 일부 날짜·조건만 대조했고, 모든 항목을 원문과 대조한 것은 아니다. 연도는 정리표에 없으면 2026년으로 가정했다.
- 포스터 12장은 모두 `images/`(약 13MB)에 있다. RISE 창업동아리(`r04`) 포스터는 사용자가 직접 제공한 최초 모집 포스터라 마감이 3/20로 적혀 있고, 신청 마감일은 연장 공고 기준(3/27)을 쓴다.
- 모바일 화면 배치는 브라우저 에뮬레이션과 DOM 클릭으로 확인했다. 실제 폰에서는 `index.html`만 열었을 때 스타일이 빠지는 문제가 발견되어 `standalone.html`을 만들었다. `standalone.html`을 실제 폰에서 연 확인은 아직 없다(에뮬레이션에서는 파일 하나만 다른 폴더에 두고 열어 동작을 확인했다). iOS Safari는 확인하지 않았다.
- `standalone.html`의 포스터는 축소본이라 작은 글씨는 원본보다 흐릿할 수 있다. 상세 화면의 "원본 이미지 보기" 링크는 인터넷 연결이 필요하다.
- 조건 선택지(관심 분야 5종, 학년 4종, 일정 슬롯 3종)와 결합 규칙은 기획서에 명시되지 않아 가정한 값이다.
- 후보 저장, 알림, 비교 화면, 실시간 수집, AI 추천은 범위 밖이다.

## 데이터

19건 = **실제 공고 12건**(교내 5건 `r01`~`r05`, 교외 7건 `e01`~`e07`) + **예시(가상) 공고 7건**(`s01`~`s07`)이다.

- 실제 공고는 사용자가 제공한 공고 정리표를 바탕으로 했다. 화면에는 "공고 원문을 요약한 정보입니다. 지원 전에 원문에서 다시 확인하세요."를 표시한다.
- 예시 공고는 학년·재학 상태·대상 학과 필터를 확인하려고 만든 가상 데이터다. "예시" 배지와 "예시 데이터입니다. 실제 공고가 아닙니다."를 표시하고, 원문 링크와 이미지는 없다.

- 포스터 이미지는 각 기관의 이미지이므로 프로토타입·수업 용도로만 사용하고 출처(`image.origin`)를 함께 보관한다.

| 필드 | 설명 |
|---|---|
| `id`, `title` | 공고 식별자, 활동명 |
| `scope` | `campus`(교내) / `external`(교외) |
| `interests[]` | 관심 분야 |
| `eligibility` | 지원 자격. `text`는 표시용, `grades[]`는 학년 필터용(`[1,2,3,4]` = 학년 제한 없음, `null` = 확인 필요), `status`는 재학 상태 필터용, `departments`는 대상 학과 필터용 |
| `eligibility.status` | 재학 상태별 지원 가능 여부 `{enrolled, leave, grad, general}`. `true` 가능, `false` 제외, `null` 확인 필요 |
| `eligibility.departments` | `null` = 전 학과·학과 무관(항상 표시), `["공과대학", "컴퓨터학부"]` = 해당 단과대학·학부·학과 한정 |
| `schedule` | 활동 일정(참여 가능 여부 판단용). `text`는 표시용, `slots[]`는 필터용(`[]` = 요구 시간대 없음, `null` = 확인 필요) |
| `deadline` | 신청 마감일 `YYYY-MM-DD`(지원 기한 확인용). 활동 일정과 별도 필드 |
| `deadlineNote` | 마감 시각 등 보충(선택). 예: `18:00까지` |
| `sourceUrl`, `sourceLabel` | 원문 링크와 표시 문구(선택). 원문이 없으면 `sourceUrl`은 `null`이고 "원문 링크 없음"으로 표시 |
| `attachments[]` | 추가 링크 `[{label, url}]`(선택) |
| `image` | 포스터 `{src, alt, origin}`(선택). `origin`은 이미지 출처 주소 |
| `isSample` | 예시 데이터 여부 |

`grades`, `slots`가 `null`이면 필터에서 숨기지 않고 통과시킨다.

## 페이지 나누기

- 목록 위의 "한 페이지에 보기"에서 **10개 / 20개 / 50개**를 고른다(기본 10개).
- 결과가 선택한 개수보다 많으면 목록 아래에 **이전 · 페이지 번호 · 다음** 버튼이 나온다. 좁은 화면(960px 이하)에서는 번호 대신 "2 / 2 페이지"를 보여 준다. 결과 건수 옆에 "1–10번째 표시"처럼 현재 범위를 표시한다.
- 조건을 바꾸거나 초기화하면 1페이지로 돌아가고, 개수를 바꿔도 1페이지로 돌아간다. 선택한 공고가 다른 페이지에 있어도 상세는 그대로 유지된다.
- 페이지 나누기 계산은 `filter.js`의 `paginate(list, page, size)`에 있고, 범위를 벗어난 페이지는 가까운 유효한 페이지로 맞춘다.
- 현재 19건이므로 10개씩이면 2페이지(10 + 9), 20개·50개씩이면 한 페이지다.

## 필터 규칙

- 서로 다른 조건 사이는 AND, 같은 조건 안의 복수 선택은 OR
- 선택하지 않은 조건은 거르지 않음
- 일정은 공고가 요구하는 슬롯이 모두 선택한 슬롯에 포함될 때 통과
- 재학 상태는 선택한 상태 중 하나라도 `true` 또는 `null`이면 통과(전부 `false`일 때만 제외)
- 대상 학과는 "내 학과" 하나를 고른다. 전 학과·학과 무관(`null`, `[]`) 공고는 항상 통과하고, 학과가 한정된 공고는 내 학과 또는 소속 단과대학이 대상에 있을 때만 통과

## 확인용 데이터 구성

| 확인할 상태 | 방법 |
|---|---|
| 일정 필터로 결과가 줄어듦 | 봉사 + 학기 중 평일 저녁 → `r05` 1건 |
| 슬롯 2개 요구(방학+주말) | `r03`, `e07` |
| 일정 확인 필요 | `r01`, `r02`, `r04`, `r05`, `e01`, `e03`, `e06` |
| 참여 시간 요구 없음(`slots: []`) | `e04` |
| 자격 확인 필요(`grades: null`) | `r01`~`r05` |
| 원문 링크가 파일 | `e02`(모집 안내문 파일) |
| 추가 링크 있음 | `r04`(최초 모집 게시글), `e04`(포스터 게시글) |
| 신청 마감 전(기준일 이후) | `e01`(D-3), `e02`·`e03`(D-6), `e04`(D-15) |
| 결과 없음 | 봉사 + 일반인(비재학) → 0건. ‘봉사’ 해제 → 7건, ‘일반인(비재학)’ 해제 → 5건 |
| 재학 상태로 결과가 줄어듦 | 휴학생 → 13건, 대학원생 → 13건, 일반인 → 7건(`e01`, `e02`, `e04`, `e06`, `r01`, `r02`, `s07`), 재학생 → 17건(`s06`·`s07` 제외) |
| 재학 상태 명시 제외 / 가능 | `e03`(휴학생·대학원생 제외), `e06`(휴학생 참여 가능) |
